Unicorn theme report

A fourth mode on the existing theme switcher: a light base with pastel pink, lilac and mint surfaces, a rainbow header and rainbow primary buttons. Built in five phases from docs/specs/unicorn-theme-phases.md.

Outcome

Done. All spec acceptance criteria pass. bun test passes (55 pass, 1 skip, 0 fail) and bun run check passes. Nothing has been deployed.

How it behaves

Auto → Light → Dark → Unicorn (sparkle icon) → Auto
  • The choice is stored in localStorage under theme as unicorn.
  • The init script in __root.tsx applies it before first paint, so a reload shows no flash.
  • Unicorn keeps the light class and adds unicorn and data-theme="unicorn". Auto only ever resolves to light or dark.
  • Unknown stored values fall back to auto.

Changes from the plan

  • The button aria-label now names the next mode, for example "Click to switch to unicorn mode".
  • The header uses a 30% white wash over the rainbow and dark plum nav links, so both options in the plan were applied.
  • Rainbow buttons get a small brightness and saturation lift on hover, because the existing hover colour is hidden under the gradient.
  • The decoration rules sit in a block at the end of styles.css to satisfy the linter's specificity rule.
  • The .unicorn block also themes popover, secondary, muted, input, sidebar and chart tokens, so the whole UI is covered.
  • bun run check failed on the baseline because Node was not installed: wrangler ran under Bun and wrote an HTML page into worker-configuration.d.ts. Installing Node (with approval) fixed it.

Not done

  • Not deployed. The spec says to deploy only on request.
  • The toaster and charts were not inspected in Unicorn mode. They use the light theme, which Unicorn keeps.
  • The unrelated apps/web/wrangler.jsonc change (real D1 database ID) is still uncommitted.
